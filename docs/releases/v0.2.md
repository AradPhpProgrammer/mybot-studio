# MyBot Studio v0.2 — Prerelease

**Release type:** GitHub prerelease, not stable.  
**Intended tag/title:** `v0.2` / `v0.2 — Prerelease`.  
**Application metadata:** `0.2.0` (the GitHub prerelease flag indicates release maturity).  
**Publication status:** prepared release notes; this file does not assert that a tag or GitHub release has been published.

## Highlights

- Dedicated `action_keyboard` canvas node and shared inline/reply keyboard designer, including row/button reordering and semantic button colors.
- Keyboard predecessor validation in the editor and runtime. Reply keyboards belong to sends; edits accept inline markup only.
- Responsive layout refinements for narrow screens and floating preview bounds, with RTL and light/dark theme work.
- Unified graph undo/redo for structure, message fields and keyboard definitions. Snapshot-based saving keeps edits made during an in-flight save dirty and prevents a stale save from marking another bot clean.
- Zoom/pan-aware context-menu insertion and separate reporting of flow-save errors versus Telegram command-sync errors.

## Telegram compatibility

A send accepts only **one `reply_markup`**. Inline and reply keyboards are not merged into a single request or simulated by silently sending an extra message. An already visible reply keyboard can coexist on screen with a later inline message.

Connect Keyboard directly after Send Message or Edit Message; only inline mode is valid for edits. The runtime resolves the executed message predecessor rather than an unrelated branch's latest message. Text, media captions and markup-only edits need their corresponding Telegram methods. Browser simulation does not certify live Bot API delivery or pixel-identical rendering.

Existing embedded keyboard definitions and legacy `action_reply_keyboard` nodes remain supported; review older flows and test representative sends, callbacks and edits before migrating live bots.

## Install / upgrade

The README commands target `main` **after** the v0.2 merge and default-branch migration. At documentation preparation, the default branch was `master`; the maintainer must publish the migration before advertising these commands as available. Keep the earlier v0.1 history identifiable and do not describe v0.2 as stable.

Use the complete repository checkout. From its root:

- Windows: `.\start-local.bat`
- Linux / macOS: `bash start-local.sh`
- Both invoke `start-local.py`. Add `--check` for dependency/import preparation only: it does not launch services, is not read-only and does not prove startup or health.
- Python 3.10+ with pip/venv, Node.js 18+ with npm (prefer a supported LTS), and network access for dependencies are needed; uv is optional. Keep port 8000 free because the launcher may terminate its listener.

Back up configuration, databases and uploads; test a copy first. Deployment installers overwrite `.env`, so they are not a safe blind upgrade command. Review changes and rebuild **all affected services**, including the bot engine for this runtime update. Both updater scripts now rebuild the panel and bot worker, stop on command failure, and follow the current Git upstream with `git pull --ff-only`; they refuse a dirty working tree. Worker restart may briefly interrupt service. `--check` validates Compose configuration without pulling, building or restarting.
