# MyBot Studio

Визуальный конструктор Telegram-ботов для самостоятельного размещения: ReactFlow, FastAPI и Aiogram.

[English](README.en.md) · [فارسی](README.fa.md) · [العربية](README.ar.md) · [Русский](README.ru.md)

> **v0.2 — предварительный выпуск (prerelease), не стабильная версия.** Инструкции рассчитаны на `main` после слияния v0.2 и смены ветки по умолчанию. До публикации этой миграции команда клонирования `main` недоступна; не подменяйте её веткой `master`. Перед тестированием сохраните резервную копию данных.

## Новое в v0.2

- **Отдельный узел Keyboard** (`action_keyboard`): inline-клавиатуры и обычные reply-клавиатуры, строки, подписи, идентификаторы и стили Telegram (`primary`, `success`, `danger`). Подключайте непосредственно после Send Message или Edit Message; reply-клавиатура допустима только после Send Message.
- **Общий редактор клавиатуры** в узле и вкладке Edit предпросмотра, с перестановкой кнопок и строк. Сохраняется поддержка встроенных клавиатур старых сообщений и прежних узлов reply-клавиатуры.
- **Адаптивная компоновка** узких панелей, диалогов и плавающего предпросмотра; доработки светлой/тёмной темы и RTL. Это не гарантия одинакового отображения на всех устройствах.
- **Отмена/повтор и сохранение снимка графа** включают текст, определения кнопок и структуру. Успешное сохранение помечает сохранённым только отправленный снимок; более поздние правки остаются несохранёнными.
- **Проверка соединений** объясняет неверное подключение клавиатуры. Вставка узла через контекстное меню учитывает масштаб и смещение холста.

## Правила Telegram

Каждая отправка содержит **один `reply_markup`**: inline- и reply-клавиатуры нельзя объединить в одном запросе. Уже открытая reply-клавиатура может оставаться под следующим сообщением с inline-кнопками — это не два типа разметки в одном сообщении. Узел Keyboard относится к выполненному предшествующему узлу сообщения, а не сообщению из другой ветви.

**Редактирование сообщений поддерживает только inline-клавиатуры.** Методы редактирования Telegram не принимают reply-клавиатуру. Для текста, подписи медиа и только кнопок используются разные методы; при изменении только кнопок нельзя отправлять пустой текст. Локальный симулятор не подтверждает доставку в Telegram.

## Установка

### Исходники предварительного выпуска

Установите Git и после миграции ветки выполните:

```bash
git clone --branch main https://github.com/AradPhpProgrammer/mybot-studio.git
cd mybot-studio
```

### Локальный запуск без Docker

Из **корня репозитория**, не из `backend/` или `frontend/`:

**Windows (CMD / PowerShell)**
```bat
.\start-local.bat
```

**Linux / macOS**
```bash
bash start-local.sh
```

Нужны Python **3.10+** с `pip` и `venv`, Node.js **18+** с npm (требование Vite 5); рекомендуется поддерживаемая LTS-версия Node. Инструменты должны быть в PATH. `uv` необязателен, доступен резервный путь через pip. Для загрузки зависимостей нужен интернет, а для настоящих ботов — доступ к Telegram. Самостоятельное размещение не означает автономную работу Telegram без сети.

Обе оболочки вызывают **`start-local.py`**. Он создаёт `.env`, если файла нет, подготавливает `backend/.venv`, устанавливает зависимости Python, проверяет импорт сервера и устанавливает зависимости интерфейса, если отсутствует `node_modules`. Обычный запуск поднимает worker и API, ждёт ответа `127.0.0.1:8000`, затем запускает Vite (обычно `http://localhost:5173`). При ошибке API не запускайте один интерфейс в обход проблемы. Освободите порт 8000: программа запуска может завершить слушающий его процесс.

Только проверка зависимостей и импорта:

```bat
.\start-local.bat --check
```
```bash
bash start-local.sh --check
```

**`--check` не запускает worker, API или интерфейс и не проверяет работоспособность сервисов.** Он может создавать конфигурацию и виртуальное окружение, устанавливать пакеты и импортировать серверный код; это не режим только чтения. Наличие `node_modules` не означает полной проверки установленных версий.

### Linux VPS / Docker

Используйте полный клон выше, изучите `install.sh` и выполните из корня:

```bash
sudo bash install.sh
```

Скрипту нужны соседние каталоги `deploy/` и `backend/`; не запускайте отдельно скачанный установщик через pipe из curl. Он запрашивает параметры подключения, администратора и необязательного прокси, затем собирает сервисы Docker. Вопрос о домене/SSL **не выпускает сертификат**: настройте и проверьте HTTPS отдельно. В Windows с Docker/Compose изучите и запустите `install.bat`; для обычной локальной разработки нужен `start-local.bat`.

Это не защищённая по умолчанию промышленная сборка. Замените стандартные пароли и ключ подписи, проверьте действующую конфигурацию, ограничьте доступ к панели и сохраните `.env`, базы и загрузки перед обновлением. Не публикуйте токены ботов, пароли и приватные журналы. Отдельный worker не гарантирует отсутствие простоев; изменения движка требуют обновления worker. См. [примечания к выпуску](releases/v0.2.md).

## Работа в Studio

1. Добавьте бота со своим токеном BotFather и откройте Studio.
2. Соедините триггер с Send Message, затем с Keyboard. После Edit Message выбирайте только inline.
3. Сохраните изменения, проверьте команды/callback в симуляторе и отдельно проверьте доставку тестовым ботом.
4. Перед использованием заблокированных узлов переменных/базы включите хранение пользовательских переменных в настройках бота.

| Действие | Клавиши |
| --- | --- |
| Отмена изменения графа | Ctrl+Z |
| Повтор | Ctrl+Shift+Z / Ctrl+Y |
| Сохранить снимок | Ctrl+S / Ctrl+Shift+S |

В macOS поддерживаются аналоги с Cmd. Поля редактирования графа используют общую историю; посторонние настройки и текст симулятора сохраняют нативную отмену текста. Предупреждение при закрытии зависит от браузера и не является автосохранением.

## Архитектура, языки и расширения

React/Vite и ReactFlow работают с Python API и Aiogram worker. Для каждого бота есть отдельное SQLite-хранилище (`bot_{id}.db`); JSON-переменным не нужен отдельный сервер БД. В Docker панель и worker разделены. Прокси может помочь в ограниченной сети, но не гарантирует соединения.

Английские, персидские, арабские и русские переводы находятся в `frontend/src/locales/`, серверные языковые файлы и шрифты — под `backend/`. Плавающее превью поддерживает редактирование, симуляцию и сворачивание; его вид приблизителен.

[Каталог плагинов MyBot](https://github.com/AradPhpProgrammer/mybot-plugins) содержит расширения и шаблоны сообщества. Проверяйте сторонний код и разрешения перед установкой.
