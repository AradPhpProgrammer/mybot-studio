# MyBot Studio

منصة بصرية ذاتية الاستضافة لبناء بوتات تيليجرام باستخدام ReactFlow وFastAPI ومحرك Aiogram.

[English](README.en.md) · [فارسی](README.fa.md) · [العربية](README.ar.md) · [Русский](README.ru.md)

> **v0.2 إصدار تمهيدي (prerelease)، وليس إصداراً مستقراً.** تستهدف التعليمات فرع `main` بعد دمج v0.2 وتغيير الفرع الافتراضي. قبل نشر هذا الانتقال لن يتوفر أمر استنساخ `main`؛ لا تستبدله بصمت بفرع `master`. احتفظ بنسخة احتياطية قبل التجربة.

## الجديد في v0.2

- **عقدة Keyboard مستقلة** (`action_keyboard`): تصميم لوحة inline أو reply مع صفوف وتسميات ومعرّفات وأنماط أزرار تيليجرام (`primary` و`success` و`danger`). اربطها مباشرة بعد Send Message أو Edit Message؛ لوحة reply تتطلب Send Message.
- **محرر مشترك للوحة الأزرار** في العقدة وتبويب Edit بالمعاينة، مع إعادة ترتيب الصفوف والأزرار. يستمر دعم بيانات الأزرار المضمنة القديمة وعقد reply السابقة.
- **تحسينات التصميم المتجاوب** للوحات الضيقة والنوافذ والمعاينة العائمة، مع تحسين الوضع الفاتح/الداكن واتجاه RTL. لا يعني ذلك تطابق العرض على جميع أجهزة تيليجرام.
- **التراجع والإعادة وحفظ لقطة المخطط** تشمل نص الرسالة وتعريفات الأزرار وبنية المخطط. الحفظ الناجح يعتمد اللقطة المرسلة فقط؛ التعديلات التي تحدث أثناء الحفظ تبقى غير محفوظة.
- **التحقق من الاتصالات** يوضح الربط غير الصحيح للوحة؛ إدراج العقد من قائمة النقر الأيمن يراعي تكبير مساحة العمل وتحريكها.

## قواعد لوحات تيليجرام

لكل إرسال **`reply_markup` واحد فقط**؛ لا يمكن دمج inline وreply في الطلب نفسه. قد تبقى لوحة reply السابقة ظاهرة أسفل رسالة لاحقة بأزرار inline، لكن هذا لا يعني أن الرسالة تحمل النوعين. ترتبط عقدة Keyboard بعقدة الرسالة السابقة المنفذة في مسارها، لا برسالة من فرع آخر.

**تعديل الرسائل يدعم لوحات inline فقط.** لا تقبل طرق تعديل تيليجرام لوحة reply. تعديل النص أو وصف الوسائط أو الأزرار وحدها يستخدم طرقاً مختلفة؛ تعديل الأزرار فقط لا ينبغي أن يرسل نصاً فارغاً. المحاكي المحلي ليس دليلاً على نجاح التسليم في تيليجرام.

## التثبيت

### مصدر الإصدار التمهيدي

ثبّت Git ثم استنسخ الفرع بعد الانتقال:

```bash
git clone --branch main https://github.com/AradPhpProgrammer/mybot-studio.git
cd mybot-studio
```

### التشغيل المحلي دون Docker

نفّذ من **جذر المستودع**، وليس `backend/` أو `frontend/`:

**Windows (CMD / PowerShell)**
```bat
.\start-local.bat
```

**Linux / macOS**
```bash
bash start-local.sh
```

المتطلبات: Python **3.10+** مع `pip` و`venv`، وNode.js **18+** مع npm (متطلب Vite 5). يوصى بإصدار LTS مدعوم من Node. يجب أن تكون الأدوات في PATH. أداة `uv` اختيارية مع الرجوع إلى pip. تنزيل الاعتماديات يحتاج شبكة، والبوت الحقيقي يحتاج الوصول إلى تيليجرام؛ الاستضافة الذاتية لا تعني أن تيليجرام يعمل دون إنترنت.

كلا الملفين يستدعي **`start-local.py`**. ينشئ `.env` إذا لم يوجد، ويجهز `backend/.venv` واعتماديات Python، ويفحص استيراد الخلفية، ويثبت اعتماديات الواجهة إذا لم يوجد `node_modules`. التشغيل العادي يبدأ worker وAPI، وينتظر استجابة `127.0.0.1:8000` ثم يبدأ Vite (عادةً `http://localhost:5173`). لا تتجاوز عطل API بتشغيل الواجهة وحدها. اترك المنفذ 8000 خالياً؛ قد يوقف المشغّل العملية التي تستمع إليه.

فحص الاعتماديات والاستيراد فقط:

```bat
.\start-local.bat --check
```
```bash
bash start-local.sh --check
```

**`--check` لا يشغّل worker أو API أو الواجهة، ولا يثبت سلامة الخدمات.** قد ينشئ إعدادات وبيئة افتراضية ويثبت حزماً ويستورد كود الخلفية؛ ليس للقراءة فقط. وجود `node_modules` لا يعني فحصاً كاملاً لإصدارات الحزم المثبتة.

### Linux VPS / Docker

استخدم الاستنساخ الكامل أعلاه، راجع `install.sh` ثم شغّل من الجذر:

```bash
sudo bash install.sh
```

يحتاج المثبّت ملفات `deploy/` و`backend/` المجاورة؛ لا تشغّل سكربتاً منفرداً محمّلاً عبر pipe من curl. يسأل عن الاتصال وإعدادات المسؤول والبروكسي الاختياري، ثم يبني خدمات Docker. سؤال النطاق/SSL **لا يصدر شهادة تلقائياً**؛ اضبط HTTPS وتحقق منه بشكل منفصل. على Windows مع Docker/Compose، راجع وشغّل `install.bat`؛ للتطوير المحلي المعتاد استخدم `start-local.bat`.

هذا الإصدار التمهيدي غير محصّن للنشر العام افتراضياً. غيّر بيانات الدخول الافتراضية ومفتاح التوقيع، وتحقق من الإعدادات الفعلية، وقيّد الوصول إلى اللوحة، وانسخ `.env` وقواعد البيانات والملفات المرفوعة قبل التحديث. لا تنشر توكنات البوت أو كلمات المرور أو السجلات الخاصة. فصل worker لا يضمن انعدام الانقطاع؛ تغييرات المحرك تتطلب تحديث worker أيضاً. راجع [ملاحظات الإصدار](releases/v0.2.md).

## العمل داخل Studio

1. أضف بوتاً بتوكنك الخاص من BotFather وافتح Studio.
2. اربط المشغّل بـSend Message ثم Keyboard. بعد Edit Message اختر inline فقط.
3. احفظ النص والأزرار واختبر الأوامر وcallback في المحاكي، ثم تحقق من التسليم الحقيقي ببوت تجريبي منفصل.
4. فعّل تخزين متغيرات المستخدم من إعدادات البوت قبل استخدام عقد المتغيرات/قاعدة البيانات المقيدة.

| الإجراء | الاختصار |
| --- | --- |
| التراجع عن تعديل المخطط | Ctrl+Z |
| الإعادة | Ctrl+Shift+Z / Ctrl+Y |
| حفظ لقطة المخطط | Ctrl+S / Ctrl+Shift+S |

تُدعم بدائل Cmd في macOS. حقول تحرير المخطط تستخدم سجله؛ حقول الإعدادات غير المرتبطة ونص المحاكي تحتفظ بالتراجع النصي الأصلي. تحذير مغادرة الصفحة يعتمد على المتصفح وليس حفظاً تلقائياً.

## المعمارية واللغات والإضافات

تعمل React/Vite وReactFlow مع API بلغة Python وAiogram worker، مع تخزين SQLite منفصل لكل بوت (`bot_{id}.db`). لا تحتاج متغيرات JSON خادم قاعدة بيانات آخر. يفصل Docker بين اللوحة وworker. يمكن للبروكسي المساعدة في الشبكات المقيدة دون ضمان الاتصال.

ملفات الإنجليزية والفارسية والعربية والروسية في `frontend/src/locales/`؛ أصول اللغات والخطوط الخلفية تحت `backend/`. تدعم المعاينة العائمة التحرير والمحاكاة والتصغير والاستعادة؛ مظهرها تقريبي.

يضم [دليل إضافات MyBot](https://github.com/AradPhpProgrammer/mybot-plugins) إضافات وقوالب المجتمع. راجع الكود والصلاحيات قبل تثبيت إضافات خارجية.

## المساهمة والترخيص

افتح issue بخطوات إعادة المشكلة وسجلات منقّحة من الأسرار قبل اقتراح ميزة. شغّل اختبارات الخلفية ذات الصلة واختبارات انحدار الواجهة والبناء، وانشر النتائج الفعلية دون افتراض أعداد اختبارات ناجحة. البناء لا يغني عن اختبار المتصفح أو التسليم إلى تيليجرام.
